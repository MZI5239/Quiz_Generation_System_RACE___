% ── ABSTRACT (≤200 words) ────────────────────────────────────────────────────
\begin{abstract}
This report presents an end-to-end Reading Comprehension (RC) and Quiz Generation system built on the RACE dataset using exclusively traditional machine learning. The system implements a dual-pipeline architecture: Model A performs answer verification via a Soft-Voting Ensemble of Logistic Regression, LinearSVC, and Naive Bayes (achieving 75\% accuracy), while Model B generates plausible distractors and extractive hints using OHE cosine similarity and a 3-feature Logistic Regression scorer. A diversity penalty ensures lexically non-redundant distractors. Text generation is evaluated using BLEU (0.0164), ROUGE-L (0.1161), and METEOR (0.066). The full pipeline is deployed via a 4-screen Streamlit interface covering article input, quiz interaction, graduated hints, and an analytics dashboard with CSV export. All models are persisted via joblib and reproduce without GPU dependency.
\end{abstract}

% ── 1. INTRODUCTION ──────────────────────────────────────────────────────────
\section{Introduction \& Motivation}
The proliferation of digital learning materials has created an urgent need for automated assessment tools. Manual quiz generation is time-consuming and prone to bias. While Large Language Models (LLMs) have simplified this task, their ``black-box'' nature and high computational costs make them unsuitable for low-resource or privacy-sensitive environments \cite{race}.

Our motivation is to demonstrate that robust, interpretable RC systems can be built using classical NLP techniques alone. By leveraging the RACE dataset, we bridge the gap between simple keyword matching and complex neural understanding through feature engineering and ensemble learning.

% ── 2. RELATED WORK ─────────────────────────────────────────────────────────
\section{Related Work}
Automated Question Generation (AQG) has evolved significantly since Lai et al.\ \cite{race} released RACE. Neural approaches using BERT \cite{bert} dominate state-of-the-art benchmarks; however, earlier statistical approaches remain competitive in low-resource settings \cite{heilman}.

Evaluation of NLG systems employs BLEU \cite{bleu} for n-gram precision, ROUGE \cite{rouge} for recall-based measurement, and METEOR \cite{meteor} for semantic alignment. Scikit-learn \cite{sklearn} provides the traditional ML backbone used throughout this work. Our pipeline combines these foundations into a deployable educational tool without any neural dependency.

% ── 3. DATASET ANALYSIS ─────────────────────────────────────────────────────
\section{Dataset Analysis}
The RACE dataset contains roughly 100,000 multiple-choice questions from English exams.
\begin{itemize}
    \item \textbf{Overview}: 28,000 passages; each passage has 2--5 questions with 4 options.
    \item \textbf{Missing Values}: Less than 0.1\% null entries found and dropped during EDA.
    \item \textbf{Statistical Analysis}: Mean article length is 322 tokens (std = 118); mean question length is 11 tokens. Outliers detected via box-plot (articles $>800$ tokens) were retained but capped in feature length ratio.
    \item \textbf{Class Imbalance}: 1 correct option per 3 distractors (1:3 ratio); mitigated via \texttt{class\_weight=`balanced'}.
    \item \textbf{Split}: 80/10/10 Train/Val/Test.
    \item \textbf{Preprocessing}: Lowercasing, punctuation removal, stop-word filtering, OHE encoding, feature scaling (StandardScaler), feature selection by frequency threshold.
\end{itemize}

% ── 4. MODEL A: DESIGN / TRAINING / RESULTS ─────────────────────────────────
\section{Model A: Design, Training \& Results}

\subsection*{Feature Engineering}
Each (article, question, option) triple is represented by 6 features: cosine similarity of article vs.\ combined text, article vs.\ question, article vs.\ option, question vs.\ option, top-50 Jaccard overlap, and length ratio. All features are scaled with \texttt{StandardScaler}.

\subsection*{Classifiers}
Logistic Regression, LinearSVC, and BernoulliNB were trained with \texttt{class\_weight=`balanced'}.

\subsection*{Ensemble (Section~\ref{sec:ensemble})}
A Soft-Voting ensemble of calibrated SVM $+$ LR $+$ NB achieves the highest raw accuracy.

\subsection*{Unsupervised}
K-Means ($k=4$, Silhouette=0.37) and Gaussian Mixture Model ($k=4$) were applied to discover latent question clusters. Label Propagation (10\% labeled, Macro F1=0.81) demonstrates the semi-supervised capability.

% ── 5. MODEL A: ENSEMBLE ────────────────────────────────────────────────────
\section{Model A: Ensemble Strategy}
\label{sec:ensemble}
\textbf{Strategy}: Soft Voting averaging calibrated probability outputs from LR, SVM$_{\text{cal}}$, and NB.

\textbf{Improvement}: The Ensemble achieves 75\% accuracy vs.\ 53\% for individual models, demonstrating the complementary strength of linear boundaries and probabilistic outputs.

% ── 6. MODEL B: DESIGN / TRAINING / RESULTS ─────────────────────────────────
\section{Model B: Distractor \& Hint Generation}

\subsection*{Candidate Extraction}
Article sentences are segmented by punctuation. Candidates with OHE cosine similarity in the ``medium-band'' [0.05, 0.55] relative to the correct answer are selected as plausible distractors.

\subsection*{Feature Engineering for Ranking}
Each candidate is scored with 4 features: (a) OHE cosine similarity to correct answer, (b) character-level match score, (c) passage word frequency, (d) length ratio. A Logistic Regression ranker selects the top-3 non-answer candidates.

\subsection*{Diversity Penalty}
A token-overlap diversity penalty ($>$60\% overlap threshold) prevents trivially similar distractors, ensuring lexical diversity.

\subsection*{Hint Scorer}
A 3-feature Logistic Regression (keyword overlap, sentence position, sentence length) ranks sentences by relevance. The top-3 are surfaced as graduated hints (General $\to$ Specific $\to$ Near-Explicit).

\subsection*{Evaluation (BLEU/ROUGE/METEOR)}
\begin{itemize}
    \item BLEU: 0.0164 \quad ROUGE-1: 0.1214 \quad ROUGE-L: 0.1161
    \item METEOR: 0.0661 (evaluated on 20-sample test set)
\end{itemize}

% ── 7. UI DESCRIPTION ───────────────────────────────────────────────────────
\section{UI Description}
Four-screen Streamlit interface:
\begin{enumerate}
    \item \textbf{Article Input}: Text area for paste/upload; random RACE sample loader; Submit triggers full Model A+B inference with spinner.
    \item \textbf{Quiz View}: Generated question displayed; 4 options (A--D) as radio buttons; Check button; colour-coded correct/incorrect feedback; confidence score table.
    \item \textbf{Hint Panel}: Progress bar; 3 graduated hints revealed one-by-one; ``Reveal Answer'' button locked until all hints are shown.
    \item \textbf{Analytics}: Model comparison table; inference latency metrics; session log table; CSV export button.
\end{enumerate}

% ── 8. EVALUATION & DISCUSSION ──────────────────────────────────────────────
\section{Evaluation \& Discussion}
Answer verification achieves 75\% accuracy via the Ensemble, well above the 25\% random baseline. Low BLEU scores reflect the limitations of rule-based template generation; however, ROUGE-L of 0.116 indicates the templates capture moderate structural similarity to ground-truth questions. METEOR of 0.066 suggests partial semantic overlap. The silhouette score of 0.37 for K-Means indicates meaningful latent clusters in the feature space.

% ── 9. LIMITATIONS & FUTURE WORK ────────────────────────────────────────────
\section{Limitations \& Future Work}
\textbf{Limitations}: Rule-based templates produce repetitive question forms. The 3.6GB Word2Vec model is infeasible on low-RAM machines, requiring the OHE fallback. Scikit-learn version mismatch (1.6 vs.\ 1.8) produces pickle warnings but no functional errors.

\textbf{Future Work}: POS-tagging for syntactically accurate question templates; stacking meta-classifier over base models; active learning to reduce labeled data requirements; TF-IDF as an alternative to OHE for better semantic sensitivity.

% ── 10. CONCLUSION ───────────────────────────────────────────────────────────
\section{Conclusion}
This project demonstrates a full-cycle NLP pipeline using traditional machine learning. Without any deep learning, the system achieves a functional 75\% verification accuracy, generates plausible distractors with diversity control, provides graduated hints, and is deployed via a polished 4-screen UI. The work confirms that rigorous classical feature engineering combined with ensemble methods remains competitive for educational NLP tasks.
